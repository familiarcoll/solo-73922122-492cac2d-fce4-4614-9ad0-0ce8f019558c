# 病例交叉表安全交付工具

面向公共卫生数据分析员的交付工具：把「地区 × 年龄段」病例交叉表转换为可安全交付的
表格 —— 保留行合计、列合计与总计，同时遮盖小人数格，并保证**每个被遮盖格都至少有
两种与公开数值及合计相容的正整数取值**，合作机构无法反推出被遮盖的真实人数。

## 快速开始（Docker Compose）

```bash
docker compose up --build
```

然后浏览器访问 <http://localhost:8000> ，上传 CSV（或直接在页面粘贴内容），
即可在线预览交付表并下载同内容 CSV。

区域合计区间查询入口为 <http://localhost:8000/inquiry>（首页也有链接）。

停止服务：

```bash
docker compose down
```

## 输入格式

- 首行为年龄段标签，首列为地区标签，左上角为角标（可为空，原样保留到输出）；
- 数据区为 **2～4 行 × 2～4 列** 的非负整数；
- 行标签（地区）互不重复，列标签（年龄段）互不重复；
- UTF-8 编码（可带 BOM），文件不超过 256 KB。

示例（见 `samples/example_ok.csv`）：

```csv
地区,0-17岁,18-64岁,65岁以上
甲区,5,1,0
乙区,2,7,3
丙区,4,6,8
```

对应交付表（`*` 为被遮盖格）：

```csv
地区,0-17岁,18-64岁,65岁以上,合计
甲区,*,*,0,6
乙区,*,*,3,12
丙区,4,6,8,18
合计,11,14,11,36
```

## 遮盖规则

1. 人数为 **1 或 2** 的格子必须遮盖；**零格保持公开**；
2. 从其余正数格（≥3）中**追加最少数量的遮盖**；
3. 追加数量相同时，把追加格坐标按（行、列）顺序排列，取**字典序最小**的方案；
4. 交付表保留行合计、列合计与总计；
5. 每个被遮盖格在与公开数值及合计相容的正整数赋值中，至少有两种不同取值
   （否则该格会被合计唯一确定，等同于泄露）；
6. 若不存在满足条件的方案（例如某行只有一个正数格），或输入非法，
   页面会说明原因，且**不会显示原始人数**。

## 算法原理

把被遮盖格看作「行—列」二部图上的边。公开格取值与行/列合计固定后，被遮盖格的
所有相容赋值构成运输多面体 `{x ≥ 1, 行和/列和守恒}` 的整数点。以真实赋值为初始
可行流（每条被遮盖边预流下界 1），其余可行流与真实赋值之差恰好是残量图中的环流，
因此被遮盖格 `e=(i,j)`：

- 能取到「真值 + 1」 ⟺ 残量图（删去 e 的两条弧）中存在 `列j → 行i` 路径；
- 能取到「真值 − 1」 ⟺ 真值 ≥ 2 且存在 `行i → 列j` 路径。

两个方向都不可行 ⟺ 该格被唯一确定。判定只需整数可达性查询，精确无浮点误差。
求解时先在「全部正数格都遮盖」的最大集合上筛掉永远不可遮盖的格子，再按
「追加数量升序、同数量按坐标字典序」枚举候选子集，首个全部满足条件的即为答案。

## 区域合计区间查询（`/inquiry`）

分析员手里只有**已发布的遮盖交付表**时，可用该功能评估所选人群的病例负担：

1. 上传交付 CSV：数据区为 **2～4 行 × 2～4 列**，每格为非负整数或 `*`，
   保留行合计、列合计与总计（末列、末行、右下角，合计标签均为“合计”）；
2. 在页面勾选**至少两个地区（行）与至少两个年龄段（列）**；
3. 系统在所有“`*` 格填正整数、且与公开格及行/列/总计相容”的填法中，
   求所选交叉区域总人数**真正可达到的最小值与最大值**；
4. 两端相同则显示“确定的区域合计”；结果**不列出任何遮盖格的单格人数**；
5. 若公开格与合计没有相容填法，或文件格式错误，页面说明原因且不返回区间。

示例（见 `samples/example_delivery_range.csv`）：

```csv
地区,0-17岁,18-64岁,65岁以上,合计
甲区,*,*,3,9
乙区,*,4,*,10
丙区,2,*,*,9
合计,7,10,11,28
```

选择「甲区、丙区」×「0-17岁、18-64岁」时，交叉区域合计可达 **9 ～ 12** 人；
选择全部行与全部列时，区域合计就是总计 28（确定值）。

### 区间求解原理

先给每条被遮盖边预流正整数下界 1，得到行节点剩余供给
`a_i = 行合计 − 公开格之和 − 本行遮盖格数`、列节点剩余需求
`b_j = 列合计 − 公开格之和 − 本列遮盖格数`，剩余部分是一个标准的二部运输问题：

- 源点 → 行 i 容量 `a_i`；行 i → 列 j（被遮盖边）容量为残余总量；
- 列 j → 汇点容量 `b_j`。

最大流达到总量当且仅当原表存在相容填法（同时校验行合计之和、列合计之和
均等于总计）。把所选矩形区域内的被遮盖边单位费用置 1、其余置 0，
**最小费用流**给出区域内遮盖人数的最小增量，对费用取负再求一次最小费用流
得到最大增量；加上区域内公开格与遮盖格下界的固定人数，即为可达区间的两端。
全部为整数运算，无浮点误差；网络至多 10 个节点、16 条边，瞬时完成。

## 本地开发（不用 Docker）

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

运行测试（需额外安装 `pytest`、`httpx`）：

```bash
pip install pytest httpx
pytest tests/ -q
```

测试包含与暴力枚举的随机交叉验证：对大量随机小表，逐一核对
「每个被遮盖格的可行取值集合」与「最少追加 + 字典序最小」的结论。

## 项目结构

```
├── app/
│   ├── main.py          # FastAPI 应用：遮盖上传/预览/下载 + 区域区间查询
│   ├── masking.py       # 核心遮盖算法
│   ├── inquiry.py       # 交付表解析、相容性判定与区域区间（最小费用流）
│   ├── csvutil.py       # CSV 解析校验与交付表渲染
│   ├── templates/       # 页面模板（上传页、结果页、查询页）
│   └── static/style.css
├── tests/               # 算法与接口测试（含暴力枚举交叉验证）
├── samples/             # 示例 CSV（可解 / 无解 / 交付表 / 区间查询）
├── requirements.txt
├── Dockerfile
└── docker-compose.yml
```
